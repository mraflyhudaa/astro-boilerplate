The content layer is the part of a site most likely to rot: frontmatter drifts, slugs stop
matching filenames, and metadata quietly disagrees with the page. This starter treats the entry id
as the single source of truth.

## The loader

```ts
// src/content.config.ts
const blog = defineCollection({
	loader: glob({ pattern: '**/*.{md,mdx}', base: './src/content/blog' }),
	schema: ({ image }) =>
		z.object({
			title: z.string().min(1).max(120),
			description: z.string().min(1).max(200),
			pubDate: z.coerce.date(),
			heroImage: image().optional(),
			heroImageAlt: z.string().optional(),
			tags: z.array(z.string()).default([]),
			draft: z.boolean().default(false),
			translationKey: z.string().optional(),
		}),
});
```

The `glob` loader walks `src/content/blog` and produces ids such as `en/hello-world`. From that id
the site derives:

1. the locale, used for routing and `hreflang`;
2. the slug, used for the URL;
3. the path, used by cards, RSS, and the OG endpoint.

Because all three are derived, renaming a file changes the URL and the feed together — no stale
links.

## Validation that fails the build

`description` is capped at 200 characters so it can be reused as the meta description. A post
without `heroImageAlt` fails the build instead of shipping an inaccessible hero image:

```ts
.refine((data) => data.heroImage === undefined || data.heroImageAlt !== undefined, {
	message: 'heroImageAlt is required when heroImage is set',
	path: ['heroImageAlt'],
})
```

## Drafts

`draft: true` entries render in development and are filtered from production builds by
`getBlogPosts()`. The same filter guards RSS and OG generation, so a draft cannot leak through a
side channel.
